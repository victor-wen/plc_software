# PLC 上位机设计规格

## 1. 项目目标

为汇川 H3U PLC 建设一套基于 Modbus RTU 的 Windows 上位机。上位机提供设备监控、运行请求、手动操作、参数设置、报警历史、产量记录、I/O 诊断和结构化 Modbus 调试终端。

PLC 始终负责自动流程、输出执行和安全联锁。上位机只读取状态并提交请求，不替代物理急停、安全门、光栅、气压检测或 PLC 内部保护。

## 2. 已确认约束

- 正式运行平台：Windows 工控机。
- 开发环境：WSL Ubuntu 24.04 x64。
- 已安装 SDK：.NET SDK 8.0.130，运行时 8.0.30。
- UI：.NET 8 WPF，不切换 Qt。
- 本地开发：WSL 构建跨平台项目、运行核心测试，并交叉编译 WPF。
- 云端构建：GitHub Actions `windows-latest` 完成全量构建、测试和 `win-x64` 发布。
- 操作方式：普通显示器和鼠标，窗口最小支持 1280x720，默认最大化。
- 串口参数：COM 口、波特率、数据位、校验、停止位、站号、超时和重试全部可配置。
- 参数数值：PLC 原始整数，不做倍率换算。
- 用户权限：不登录，但关键操作必须确认并记录审计日志。
- 历史数据：SQLite 本机保存一年，支持筛选和 CSV 导出。
- 当前没有 PLC 设备，先完成模拟开发；真实地址核对和现场联调不属于离线开发完成条件。

## 3. 技术架构

为了兼顾 WSL 开发和 Windows WPF，解决方案拆为三个产品项目和三个测试项目：

```text
PlcSoftware.Core                 net8.0
PlcSoftware.Infrastructure       net8.0
PlcSoftware.App                  net8.0-windows
PlcSoftware.Core.Tests           net8.0
PlcSoftware.Infrastructure.Tests net8.0
PlcSoftware.App.Tests            net8.0-windows
```

### 3.1 Core

包含点位定义、设备快照、连接状态、故障、参数、命令语义、轮询计划和服务接口。Core 不引用 WPF、NModbus、SerialPort 或 SQLite。

### 3.2 Infrastructure

实现 NModbus RTU、串口管理、单请求队列、模拟 PLC、SQLite、CSV 和文件配置。Infrastructure 可在 WSL 编译和测试；串口实机访问只在设备环境启用。

### 3.3 App

实现 WPF Views、ViewModels、样式、页面导航、应用生命周期、单实例和 UI 线程派发。项目目标为 `net8.0-windows`，设置 `UseWPF=true` 和 `EnableWindowsTargeting=true`。

### 3.4 数据流

```text
Modbus 轮询
  -> 原始线圈/寄存器块
  -> 解码器
  -> 不可变 DeviceSnapshot
  -> ViewModel / 报警服务 / 历史服务

UI 操作
  -> CommandService / ParameterService
  -> 校验与审计
  -> 单一 Modbus 请求队列
  -> 写入与读回确认
```

串口只能由一个通信客户端独占。轮询、看门狗、参数写入和调试终端命令必须进入同一队列，不允许并发访问串口。

## 5. 通信设计

### 5.1 轮询

- 快速组：每 250 ms 读取 D100-D110 整块。
- 工艺组：每 500 ms 读取 D200-D213 整块。
- I/O 诊断组：每 500 ms 按点表读取 X/Y 区域。
- 写命令优先进入下一次队列调度，但不能中断正在进行的 RTU 请求。
- UI 正常情况下应在 1 秒内反映关键状态变化。

### 5.2 心跳

PLC 现有逻辑为 `LD M8013` 后执行 `INC D101`。上位机只判断 D101 在 3 秒内是否变化，不假定它严格每秒增加 1。

上位机在线时约每 200 ms 更新 D106。PLC 若约 500 ms 未检测到 D106 变化，必须清除 M106-M109 并禁止手动输出，直到通信恢复且操作员重新按下命令。

### 5.3 失败和重连

- 通信状态：断开、连接中、在线、PLC 心跳异常、重连中。
- 连续 3 次请求失败后进入断线状态。
- 重连退避：1、2、5、10、30 秒，之后保持 30 秒间隔。
- 断线时冻结最后快照、显示时间戳并禁用全部写操作。
- 重连后只恢复轮询和 D106，不重放未完成的命令。
- 脉冲写入超时视为结果未知，读取状态核对，不盲目重复启动或复位。
- 参数写入后必须读回一致才报告成功。

## 6. 页面设计

### 6.1 全局状态栏

显示串口状态、PLC 心跳、模式、运行状态、总故障、屏蔽状态和当前时间。断线、故障或屏蔽必须同时使用颜色、文字和图标提示。

### 6.2 总览页

显示等待进板、进料、挡停定位、触发相机/扫码、请求放行、放行流程，高亮 D200 当前步骤，并显示关键传感器、挡停状态、当前/目标宽度、皮带速度和产量。

### 6.3 操作区

提供启动、停止、复位、急停请求、自动、手动和直通模式。按钮可用条件由连接状态、PLC 模式、运行状态和故障状态决定，PLC 做最终联锁。

### 6.4 手动页

调宽正反转、皮带点动和挡停为按住执行。只在 PLC 返回手动且非运行状态时开放。松开鼠标、切页、窗口失焦和应用退出时均尝试复位命令；PLC 看门狗负责断线兜底。

### 6.5 参数页

可编辑 D201、D202、D204、D205，显示 D203、D210、D212-D213。写入前显示旧值、新值、单位和允许范围；写回失败时保留原值并记录原因。

### 6.6 I/O 诊断页

按 X、Y、M 分组只读显示逻辑状态和中文名称。I/O 表不提供任意强制写入，手动动作只能通过手动页执行。

### 6.7 报警与历史页

故障代码如下：

| 代码 | 含义 |
|---|---|
| 0 | 无故障 |
| K1 | 急停 |
| K2 | 安全门打开 |
| K3 | 安全光栅 |
| K4 | 气压低 |
| K5 | 气缸挡停伸出超时 |
| K6 | 挡停未缩回 |
| K7 | 扫码超时 |

D110 从 0 变为非零时创建报警，从非零回到 0 时关闭报警。相同故障持续期间不重复插入。

### 6.8 通信设置页

配置串口和站号，枚举可用串口，支持连接测试。修改配置前先断开当前连接。

### 6.9 调试终端

- 支持 FC01、FC02、FC03、FC04 结构化读取。
- 支持 FC05、FC06 单点写入。
- 输入站号、零基协议地址、数量或值。
- 显示请求摘要、响应、耗时、异常码和十六进制数据。
- 写入只在 PLC 停机时允许临时解锁，每次写入确认，5 分钟无操作自动锁定。
- 所有终端命令进入统一请求队列并记录审计日志。
- 不提供任意原始 RTU 帧发送。

## 7. 持久化

SQLite 保存报警开始/恢复、操作、参数修改、通信事件、产量变化和调试命令。每天清理一年前数据。数据库异常或磁盘空间不足不能阻塞 Modbus 轮询；应用应报告存储故障并继续安全监控。

应用启动时不恢复任何保持命令或屏蔽状态。应用限制单实例，避免两个进程争用同一串口。

## 8. 开发与 CI

### 8.1 WSL

- Core 和 Infrastructure 在 WSL 原生构建和测试。
- App 使用 `EnableWindowsTargeting=true` 在 WSL 交叉编译。
- WSL 不运行 WPF 界面，不把交叉编译等同于 Windows UI 验证。

### 8.2 GitHub Actions

工作流计划包含：

- `core-tests`：`ubuntu-latest`，构建 Core/Infrastructure 并运行跨平台测试。
- `windows-build`：`windows-latest`，全量恢复、构建、测试和发布。
- 使用 `actions/checkout@v6`、`actions/setup-dotnet@v4`、`actions/upload-artifact@v4`。
- SDK 固定为 `8.0.x`，依赖生成锁定文件，CI 使用 locked restore。
- 发布目标为 `win-x64` 自包含目录包，不使用单文件发布。

## 9. 测试边界

当前离线阶段包含：

- 寄存器位解析和 32 位组合测试。
- 命令脉冲、保持、点动和不重放测试。
- 参数上下限、写入读回和失败回滚测试。
- D101/D106 心跳和回绕测试。
- K1-K7 报警转换测试。
- 模拟 Modbus 延迟、超时、异常、错误站号和断线测试。
- SQLite 保留、查询、导出和磁盘异常测试。
- GitHub Actions Windows 构建与发布验证。

PLC 到位后单独开展：

- H3U 实际功能码和零基地址核对。
- D105、D106、D213 PLC 逻辑确认。
- 逐点联调、物理断线、安全故障注入和 24 小时稳定性运行。

## 10. 验收条件

- 配置合法时模拟 PLC 可以连接并持续刷新状态。
- 关键状态在正常负载下 1 秒内显示。
- 所有命令语义、写入保护和不重放规则通过自动化测试。
- 参数越界不能写入，合法写入有读回结果和审计。
- K1-K7 报警、历史查询和 CSV 导出可用。
- 调试终端遵守停机、解锁、确认和自动锁定规则。
- WSL Core/Infrastructure 测试通过。
- GitHub Windows Runner 全量构建、测试和 `win-x64` 发布通过。
